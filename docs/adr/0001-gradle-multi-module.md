# ADR 0001. Gradle 멀티모듈 구조

- 상태: 확정
- 날짜: 2026-09-12

## 배경

Mock Supplier는 본 애플리케이션과 같은 포트에 두면 안 됨. 자기 자신을 HTTP로 호출하면서 스레드가 묶여 연동 문제로 오해할 수 있는 실패가 생기기 때문. 즉 실행 단위가 둘(통합 검색 서비스, Mock 서버) 필요하고, 저장소는 하나일 것

## 검토했다 폐기한 대안

- **단일 모듈 + 프로필로 Mock 분리**: `@Profile("mock")` 컨트롤러를 다른 포트로 띄우는 방식. 실행 단위는 분리되지만 Mock 코드가 도메인 코드와 같은 소스 트리에 섞여 어댑터 경계가 흐려짐
- **별도 저장소**: 두 저장소를 clone해야 실행 가능
- **루트를 app으로 두고 mock-supplier만 서브프로젝트로 추가**: 파일 이동이 없어 편하지만 루트가 앱이면서 부모인 구조가 어색하고, 이후 공통 모듈을 추가하기 어려움

## 결정

- 루트는 껍데기로 두고 플러그인 버전만 `apply false`로 선언
- `app`: 통합 검색 서비스 (8080)
- `mock-supplier`: 공급사 A·B Mock (9090)
- 두 모듈은 서로 의존 X

## 결과

- 실행은 `./gradlew :mock-supplier:bootRun`, `./gradlew :app:bootRun`
- 모듈 간 코드 공유는 없다. 공유가 필요해지면 `common` 모듈을 추가하되, 현재 계획에는 없음
