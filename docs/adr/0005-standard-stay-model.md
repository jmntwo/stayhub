# ADR 0005. 표준 숙박 상품 모델

- 상태: 확정
- 날짜: 2026-09-13

## 배경

두 공급사가 같은 정보를 다르게 표현하며, 표현하는 정보의 범위도 다름

| 항목 | A | B |
|---|---|---|
| 요금 단위 | 날짜별 1박 단가 | 기간 전체 총액 |
| 세금 | 별도 금액 (nightlyRate + taxAmount) | 포함. 금액 미제공, taxIncluded: true만 |
| 재고 | 날짜별 remainingRooms | 날짜별 remainingRooms |
| 조식 | breakfastIncluded | breakfastIncluded |
| 실패 | HTTP 상태 코드 | HTTP 200 + resultCode |

고객은 어느 공급사에서 왔는지와 무관하게 같은 형태의 결과를 봐야 함. 무엇을 표준으로 삼고 무엇을 버릴지 정해야 함. 두 공급사가 같은 숙소를 취급해도 그 사실을 알려주는 공통 키는 없음.

## 검토했다 폐기한 대안

요금

- **날짜별 단가를 표준으로**: B가 날짜별 요금을 주지 않아 만들 수 없음. 총액을 박수로 나누는 것은 없는 정보를 만들어내는 것이라 판단
- **A·B 필드의 합집합**: 표준 모델이 두 공급사 형식을 그대로 안고 가서 어댑터 경계가 무의미해짐. 세 번째 공급사가 오면 다시 커짐

N박 예약 가능 객실 수

- **날짜별 합계**: 첫날 3개, 둘째 날 0개면 3이 되어 예약 불가인데 가능으로 보임

예약 불가 상품

- **응답에서 제외**: 결과 개수가 재고에 따라 흔들리고, "매진"과 "공급사 장애로 조회 실패"를 고객이 구분할 수 없음

동일 숙소 병합

- **숙소명·객실 구성으로 추정해 병합**: 잘못 합치면 다른 숙소를 같은 상품으로 보여줌. 같은 객실이라도 B는 조식 포함, A는 미포함이라 상품 조건이 다름

## 결정

| 항목 | 표준 | 버림 또는 격하 |
|---|---|---|
| 요금 | 요청 기간 전체 총액, 세금 포함. A는 날짜별 (nightlyRate + taxAmount) 합산, B는 totalPrice 그대로 | B의 세금 금액은 없음. A의 날짜별 단가·세금은 선택 필드(nightly[])로 격하. 있으면 담고 없으면 null |
| 통화 | 공급사가 준 ISO 4217 코드 그대로 | 환율 변환 없음 |
| 예약 가능 객실 수 | 숙박일 전체 remainingRooms의 최솟값. 응답에 날짜가 빠지면 0 | 날짜별 재고 상세는 응답에 담지 않음 |
| 예약 불가 상품 | availableRooms: 0으로 노출 | 별도 boolean 필드는 두지 않음 |
| 동일 숙소 | 공급사별로 각각 노출. 출처 공급사와 조식 여부를 항목마다 표기 | 병합하지 않음 |
| 조식 | breakfastIncluded 그대로 | |
| 최대 인원 | maxOccupancy 그대로. 성인 + 아동 합산 기준 | |


## 결과

- 검색 응답의 요금 필드는 공급사와 무관하게 "이 기간 이 객실 타입에 내는 총액" 하나
- 비용 1: A의 날짜별 단가 정보가 표준에서 부가 정보로 내려감. 날짜별 가격 비교 기능은 A 상품에만 가능
- 비용 2: 같은 숙소가 두 번 보일 수 있음. 고객이 출처와 조식 여부를 보고 비교해야 함
- 비용 3: 재고 0인 상품이 결과에 포함되어 응답 크기가 늘어남


## AI 제안과 내 판단

- AI는 숙소명, 객실명, 최대 인원의 출처를 "실시간 응답 우선, 없으면 매핑"으로 제안함. 나는 자주 바뀌는 값이 아닌데 실시간을 우선할 이유가 없다고 판단해 매핑 단일 출처로 변경. 분기가 사라지는 효과
