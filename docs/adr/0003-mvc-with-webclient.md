# ADR 0003. Spring MVC 위에서 WebClient만 사용

- 상태: 확정
- 날짜: 2026-09-12

## 배경

외부 공급사 호출은 WebClient로 지정됨. 여러 공급사를 동시에 호출하며 타임아웃·병렬 제어를 다뤄야 함.
## 검토했다 폐기한 대안

- **WebFlux 전면 도입**: 리액티브가 필요한 구간은 공급사 호출 하나뿐. JPA가 블로킹이라 R2DBC 전환이나 별도 스케줄러 처리가 필요하고 디버깅/테스트 비용이 커짐

## 결정

- 서블릿 스택(Spring MVC) 유지. 컨트롤러, 서비스, JPA는 동기 코드
- 공급사 호출 계층만 WebClient. 공급사별, 청크별 호출을 Mono로 조합
  - 병렬: 공급사별 동시 구독, 공급사별 동시 호출 수 제한
  - 타임아웃: 연결·응답 타임아웃 + 전체 데드라인
  - 부분 실패: 실패한 공급사는 빈 결과 + 실패 표식으로 바꿔 병합
- 조합이 끝난 지점에서 한 번만 block(). 리액티브 코드는 어댑터와 조합 계층 안에만 존재

## 결과

- block() 지점이 하나라 동기 세계로 넘어오는 경계가 명확함
- 비용: 검색 요청마다 서블릿 스레드 하나가 공급사 응답을 대기. 공급사가 느릴수록 스레드 고갈에 가까워짐
- 대응: 전체 데드라인으로 점유 시간 상한. Java 21 가상 스레드로 대기 비용 제거(견고성 구현 시 검증 후 적용 예정). 그 이상은 수평 확장으로 설계
